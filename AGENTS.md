# [AGENTS.md](http://AGENTS.md)

Personal blog and portfolio for Subash Chandra Sapkota, live at [https://subashcs.com.np](https://subashcs.com.np). It's a static Astro 5 site built from the AstroWind template, using Tailwind CSS v4 and a few React islands.

## Commands

The package manager is Yarn (`yarn.lock` is committed; `package-lock.json` is gitignored). Use Node 22 (see `.nvmrc`).


| Command            | Purpose                                          |
| ------------------ | ------------------------------------------------ |
| `yarn dev`         | Start the dev server                             |
| `yarn build`       | Build the static site into `dist/`               |
| `yarn preview`     | Serve the built `dist/` locally                  |
| `yarn format`      | Run Prettier on the whole repo (`prettier -w .`) |
| `yarn lint:eslint` | ESLint (currently broken, see below)             |


To check a change, run `yarn build`. There are no tests.

`yarn lint:eslint` fails right now: ESLint 9 needs a flat config (`eslint.config.js`), and the repo still has the old `.eslintrc.js`. Don't count lint output as a passing check until the config is migrated.

## Layout

- `data/blog/*.md|*.mdx`: blog posts. The file name becomes the post id and default slug.
- `src/pages/`: routes. The blog, category, and tag routes live under `[...blog]/`, `[...categories]/`, and `[...tags]/`. Other pages include `cv.astro`, `dissertions/`, `documents/[document].astro`, and `rss.xml.js`.
- `src/components/`: split into `atoms/` (small pieces), `core/` (meta tags, theme/menu toggles, scripts), `blog/` (post lists and the single post view), and `widgets/` (homepage sections, header, footer). `widgets/Typing.tsx` is the only React component.
- `src/layouts/`: `BaseLayout`, then `PageLayout` and `BlogLayout`.
- `src/utils/`: `posts.js` loads and normalizes posts, `permalinks.js` builds every internal URL, `images.js` resolves `~/assets` image paths, `frontmatter.mjs` is the remark plugin that sets the reading time, and `documents.js` holds the metadata for `/documents/*`.
- `src/config.mjs`: `SITE` (origin, title, analytics IDs) and `BLOG` (posts per page, route prefixes, enable/disable flags).
- `src/assets/styles/base.css`: Tailwind entry point (`@import "tailwindcss"`, the typography plugin, and a class-based `dark` variant) plus shared component classes such as `.btn` and `.btn-primary`.
- `.astro/` is generated by Astro. Don't edit it by hand.



## Conventions

- Import from `src` through the `~` alias (`~/components/...`, `~/utils/...`), not long relative paths.
- Build internal links with the helpers in `~/utils/permalinks` (`getPermalink`, `getBlogPermalink`, `getCanonical`, and so on). Don't hardcode paths, because the route prefixes and trailing-slash behavior come from `src/config.mjs`.
- Formatting follows `.prettierrc`: tabs, single quotes, semicolons, 120-column lines, ES5 trailing commas. Markdown, JSON, YAML, TOML, and dotfiles use spaces instead of tabs.
- Style with Tailwind utility classes in the markup. Every style needs a `dark:` variant, since dark mode is toggled by a `.dark` class.
- Keep the site fully static (`output: 'static'`). Use React only for real client-side interactivity, and hydrate it with an Astro `client:*` directive.



## Writing a blog post

Create `data/blog/<slug>.md`, or `.mdx` if the post needs imports or components. Frontmatter:

```yaml
---
publishDate: 'Nov 07 2023'
title: 'Post title'
description: 'One or two sentence summary used for SEO and listings.'
image: '~/assets/images/<slug>/cover.png'
tags: [tag-one, tag-two]
# optional: excerpt, category, authors, canonical, slug, draft: true
---
```

- Put the post's images in `src/assets/images/<slug>/` and reference them as `~/assets/images/...`. In MDX, import them and render them with `Image` from `astro:assets`.  
If the images are not explicitly provided and need to add images then Generate images, add them in this folder and reference them in blog if required.
- `draft: true` keeps a post out of the build. Posts are sorted by `publishDate`, newest first.
- `readingTime` is filled in automatically, so don't set it.
- While writing a blog post, always look for latest data on the internet.
- Do not include outdated information. If any information looks irrelevant or outdated flag such info.



## Things to be careful with

- The CV page is deliberately privacy-limited: a preview image with the lower half blurred, plus a request form (`widgets/RequestCv.astro`). Don't link to or serve the full CV PDFs in `src/assets/documents/`, and don't expose a home address.
- `SITE.googleAnalyticsId` controls whether Partytown is loaded (`astro.config.mjs`).
- The site deploys from the `deploy` branch, and both `netlify.toml` and `vercel.json` exist. If you change the build output or headers, keep the two in sync.
